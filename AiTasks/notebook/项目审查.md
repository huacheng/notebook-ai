## D1 正确性 (Correctness)

### 已有防护（正面）

- WS 入站消息全部经 `WSClientMessageSchema.safeParse()` 校验 (`ws-handler.ts:136`)
- 并发执行守卫：每 session 同时只能执行一个 cell (`session.ts:210`)
- 路径遍历防护：`validateWorkspacePath()` 用 `realpath()` + 前缀校验
- REST 路由状态码使用规范（201/204/400/403/404/409/422/500 均覆盖）
- 授权机制完整：timing-safe 比较、一次性 WS ticket（30s TTL）、指数退避锁定

### 问题清单

| # | 位置 | 问题 | 严重度 | 状态 |
|---|------|------|--------|------|
| D1-1 | `ws-handler.ts:211-213` | WS 订阅 `sessionOwners.set()` 与 listener 注册非原子，并发订阅可能产生竞态 | LOW | 待修 |
| D1-2 | `files.ts:38`, `notebooks.ts:117` | 路径遍历攻击返回 400 而非 403（`projects.ts:174` 正确返回 403） | LOW | 待修 |
| D1-3 | `session.ts:139,151` | 裸 `catch {}` 无错误类型，应为 `catch (err: unknown)` | VERY LOW | 待修 |

### 详细说明

**D1-1 WS 订阅竞态**：两个客户端在毫秒级间隔内同时订阅同一 session，`sessionOwners.set()` 和 listener 注册之间存在窗口期。现有 takeover 检查（`ws-handler.ts:152-160`）在 readyState 为 CLOSING/CLOSED 时才生效，无法覆盖两个 OPEN 连接同时到达的情况。建议将 `sessionOwners.set()` 移入 listener 注册前或改为原子操作。

**D1-2 状态码不一致**：`files.ts:38` 和 `notebooks.ts:117` 对 "Path outside workspace" 错误返回 400（Bad Request），但这本质上是权限/访问控制问题，应返回 403（Forbidden）。`projects.ts:174` 已正确处理。

## D2 安全性 (Security)

### 已有防护（正面）

- `crypto.timingSafeEqual()` 时间安全 token 比较 (`auth.ts:98-105`)
- WS 一次性 ticket 机制（UUID + 30s TTL + 首次消费即失效）
- 指数退避限流（60s → 120s → 240s ... → 30min 上限）
- `execFile()` 代替 `exec()` 防命令注入
- DOMPurify 已用于 HTML 文件渲染和 Mermaid 图表
- SQLite 参数化查询防 SQL 注入
- `CLAUDECODE` 环境变量清除防嵌套 session

### 问题清单

| # | 位置 | 问题 | 严重度 | 状态 |
|---|------|------|--------|------|
| D2-1 | `session.ts:266` | **restart 时未传 allowedDirs**，新进程丢失跨项目目录隔离 | **CRITICAL** | ✅ 已修 |
| D2-2 | `FileViewerRender.tsx:100-121` | XLSX → HTML 经 `dangerouslySetInnerHTML` 未过 DOMPurify，可 XSS | HIGH | ✅ 已修 |
| D2-3 | `auth.ts:28-30` | `X-Forwarded-For` 无条件信任，攻击者可伪造 IP 绕过限流 | HIGH | ✅ 已修 |
| D2-4 | `ws-handler.ts` (17 处) | `String(err)` 直接发客户端，泄露栈信息和文件路径 | HIGH | ✅ 已修 |
| D2-5 | `routes/plugin.ts:103-172` | pluginKey 未校验格式，直接传入 `execClaude(['plugin', 'install', ...])` | HIGH | ✅ 已修 |
| D2-6 | `ws-handler.ts:107-117` | WS ticket 未绑定 session，任何已认证客户端可订阅任意 session | MEDIUM | 待修 |
| D2-7 | `CellOutput.tsx:15-23` | SVG 清洗用正则，不防 `<iframe>`/`<object>`/CSS 注入，应换 DOMPurify | MEDIUM | ✅ 已修 |
| D2-8 | `session.ts:141-151` | allowedDirs 从父目录 readdir 计算，不验证 symlink 逃逸 | MEDIUM | 待修 |

### 详细说明

**D2-1 restart 丢 allowedDirs（CRITICAL）**：`session.ts:266` 创建新 `AgentProcess` 时：
```typescript
session.agentProcess = new AgentProcess(engine, session.cwd, MEMORY_SYSTEM_PROMPT, model);
// ↑ 缺少第 5 个参数 allowedDirs
```
而初始创建（line 156）正确传递了 `allowedDirs`。修复方案：在 session 对象中保存 allowedDirs，restart 时复用。

**D2-2 XLSX XSS**：`XLSX.utils.sheet_to_html()` 输出直接通过 `dangerouslySetInnerHTML` 渲染，恶意 XLSX 可注入 JS。项目已依赖 DOMPurify（用于 Mermaid），只需在渲染前过一遍即可。

**D2-3 XFF 伪造**：`auth.ts:28-30` 无条件读取 `X-Forwarded-For` 作为客户端 IP，攻击者可每次请求伪造不同 IP 绕过限流。建议增加 `TRUST_PROXY` 环境变量控制。

**D2-4 错误信息泄露**：42+ 处 `sendToClient(ws, { type: 'error', message: String(err) })`，暴露：完整栈信息、文件路径、SQLite 错误详情、库版本号。应 server 端 log 详情，client 端只发通用消息。

**D2-7 SVG 正则不完整**：当前清洗 `<script>`、`on*` 属性、`javascript:` href，但不防：
- `<iframe srcdoc="...">`、`<object data="...">`、`<embed>`
- CSS `expression()` / `@import` 注入
- SVG `<animate>`/`<set>` 事件
- `<use xlink:href="data:...">`

项目已有 DOMPurify 依赖，建议替换为 `DOMPurify.sanitize(svg, { USE_PROFILES: { svg: true } })`。

## D3 可靠性 (Reliability)

### 已有防护（正面）

- agent-process 崩溃检测 + 自动重启 (`session.ts:199-206`)
- WS 重连含 ping/pong keepalive (10s interval, 4s timeout) + 事件重放 (`resume_after`)
- event-buffer 固定 500 条环形缓冲，不会无限增长
- 工具结果竞态修复：`findCellByToolUseId()` 优先查找 (commit `597118f`)
- FileWatcher / GitWatcher 引用计数，最后一个 unsubscribe 清理资源

### 问题清单

| # | 位置 | 问题 | 严重度 | 状态 |
|---|------|------|--------|------|
| D3-1 | `ws-handler.ts:813` | 客户端崩溃时 `sessionOwners` 残留，listener 函数不被 GC | MEDIUM | ✅ 已修 |
| D3-2 | `wsSlice.ts` | WS 重连固定 3s 间隔 × 10 次，无指数退避，长时间断开恢复差 | LOW | 待修 |
| D3-3 | `notebookSlice.ts` | `streamBuffer` 若丢失 `execution_complete` 消息则永不清理 | LOW | 待修 |

### 详细说明

**D3-1 listener 泄漏**：客户端异常断开（非正常 `unsubscribe`）时，`cleanup()` 通过 `ws.on('close')` 触发，会移除 watchSubscriptions 但 `sessionOwners` Map 中的条目可能残留。虽然 takeover 检查会在新连接时覆盖旧条目（检查 readyState），但闭包持有的旧 listener 函数不会被 GC。建议增加定期清理或 WeakRef。

**D3-3 streamBuffer**：`appendStreamDelta()` 往 `streamBuffer` Map 追加文本，在 `execution_complete` 时 flush。若 WS 消息丢失或 cell 状态异常转换，buffer 永不清空。建议在 cell 状态变为 completed/error 时也触发 flush。

## D4 性能 (Performance)

### 已有优化（正面）

- 无 N+1 查询：notebook 列表用 `Promise.all()` 并行加载
- 前端 Zustand 选择器粒度细，避免不必要重渲染
- FileWatcher 用 500ms debounce 去抖
- WS 推送文件列表替代 REST 轮询（commit `226dcd1`）

### 问题清单

| # | 位置 | 问题 | 严重度 | 状态 |
|---|------|------|--------|------|
| D4-1 | `ws-handler.ts:419-434` | 大文件全量 `readFile()` → base64，100MB PDF 占 133MB 内存峰值 | MEDIUM | 待修 |
| D4-2 | `session.ts` | session 无空闲超时，长期运行服务器 agent 进程不释放 | LOW | 待修 |
| D4-3 | `notebooks` 表 | `project_id` 列无索引，`listProjects` 每次 LEFT JOIN 算 count | LOW | 待修 |
| D4-4 | `wsSlice.ts` | `lastEventIndex` Map 随 session 积累，notebook 关闭后不清理 | LOW | 待修 |

### 详细说明

**D4-1 大文件内存**：`ws-handler.ts:419-434` 的文件传输流程：
```
readFile(全量) → toString('base64') → slice(CHUNK_SIZE) → WS send
```
100MB PDF = ~133MB base64 字符串在内存中。建议改用 `fs.createReadStream()` + base64 Transform 流式传输。

## D5 架构 (Architecture)

### 优势

- 三包单向依赖：`web → shared ← server`，无循环引用
- Zod schema 集中在 shared 包，REST/WS 消息共用
- 数据库开启外键约束 + WAL 模式
- AgentEngine 抽象支持 claude/gemini 切换

### 问题清单

| # | 问题 | 严重度 | 状态 |
|---|------|--------|------|
| D5-1 | 新增文件格式需改 3+ 文件（shared types + server handler + web renderer），无格式注册表 | MEDIUM | 待改进 |
| D5-2 | `ws-handler.ts` 单函数 ~800 LOC switch/case，无中间件/分发器模式 | MEDIUM | 待改进 |
| D5-3 | `uiSlice` 348 LOC 混合 7+ 正交关注点（文件 tab / 布局 / 编辑模式 / 插件面板） | LOW | 待改进 |
| D5-4 | 数据库迁移内联在 `migrate()` 中，try/catch 静默跳过已有列，无版本号管理 | LOW | 待改进 |
| D5-5 | `openNotebookByPath()` 共享逻辑放在 routes 层（`routes/notebooks.ts:33`），不够内聚 | LOW | 待改进 |

### 详细说明

**D5-1 文件格式扩展散射**：以添加 "image" 格式为例，本次 PR 需修改：
1. `packages/shared/src/types.ts` — FileOpenMetaSchema.format enum
2. `packages/server/src/ws-handler.ts` — IMAGE_EXTS + binary 检测
3. `packages/web/src/hooks/useFileStream.ts` — FileFormat type + binary 判断
4. `packages/web/src/components/FileViewerRender.tsx` — 新渲染分支

建议引入格式注册表模式，集中声明 `{ ext, mime, renderer, isBinary }`。

**D5-2 WS handler 膨胀**：ws-handler.ts 的 switch/case 涵盖 23+ 消息类型，每个 case 包含完整业务逻辑。建议提取为 `Map<string, MessageHandler>` 分发器，每种消息类型独立文件。
